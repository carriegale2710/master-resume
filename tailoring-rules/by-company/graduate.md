# **CV checklist: Graduate roles**

> Tailor your CV for a graduate, traineeship, internship or entry-level program.
> You MUST check CV follows every-resume.md first before applying the guidelines below.
> Repo rules win: numbers only from `master/metrics-log.csv` (use its "Safe wording"), no NDA-covered names, Australian English spelling, never invent a skill, date or figure.

**Headline example:** "Graduate Software Engineer | TypeScript, React, Node.js"

## **Must‑have signals**

- **One target role** named in the headline, with the stack as in the posting (only where the master supports it).
- **Education sits directly under the summary** (degree, institution, relevant units or capstone, as in the master).
- **Strongest 1–2 projects or placements come next**, with impact, not a list of coursework.
- **Eligibility is clear**: work rights on one line using `${RESUME_WORKRIGHTS}`; location and availability only if the master gives them.
- **Program keywords mirrored** (rotation, traineeship, cohort, mentoring) only where the master supports them.

## **Experience and project bullets**

- **What**: the thing you built or did, and your part in it.
- **How**: tools and methods named plainly (tech stack, testing, version control, Agile ceremonies if evidenced).
- **Why (impact)**: who used it, what it improved. Use the metrics log wording for any figure; otherwise describe the outcome without a number.
- Use **transferable evidence** when tech experience is thin: teamwork, deadlines, customer contact, part-time or retail work, only as written in the master.
- Show **learning speed**: picked up a new tool, shipped it, what changed. One concrete example beats "fast learner".
- Projects carry **no dates or years** (work-in-progress marker only if the master gives one).

## **Formatting specifics**

- One page, single column, Calibri, exported as a Word doc.
- No generic "Skills" section; never lead with Weak / exposure‑only skills.
- Links fully typed out (without `https://`), using the `${GITHUB_URL}`, `${LINKEDIN_URL}` and `${PORTFOLIO_URL}` placeholders.
- Cut older or unrelated items first so the page stays at one.
