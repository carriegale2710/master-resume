# **CV checklist: Software Engineering (role-specific only)**

> Check `every-resume.md` first (headline, what+how+why bullets, no Skills section, dates, links). Only role-specific ticks are below.
> Repo rules win: figures only from `master/metrics-log.csv` (examples are illustrative), never invent a project, tool or result.

## **Full‑Stack Software Engineer (Junior)**

**Headline example:** "Junior Full‑Stack Engineer | TypeScript, React, Node, PostgreSQL"

- [ ] Stack is the same across headline, projects and experience.
- [ ] At least 2 full‑stack projects covering frontend, backend, database (schema/migrations), auth and deployment.
- [ ] At least one project shows the whole chain (frontend, API, database, deployment, basic tests or CI), ideally with real users or a real integration (payments, third‑party API, uploads, email).
- [ ] Depth named in bullets where the master supports it: auth (sessions/JWT/OAuth), DB design (relations, indexes), host (Vercel/Render/AWS), tests/CI.
- [ ] No unextended tutorial clones (to‑do lists, weather apps).
- [ ] Experience framed as engineering impact (automation, tooling, APIs, performance, reliability), not duties.

## **Front‑End Software Engineer (Junior)**

**Headline example:** "Junior Front‑End Engineer | React, TypeScript, Next.js, Tailwind"

- [ ] Headline names framework, language, styling and tooling.
- [ ] 2–3 front‑end projects showing component architecture, state management, API integration (loading, error, empty states) and responsive, accessible UI.
- [ ] Accessibility or DX shown (a11y checks, component library, Storybook, design system use), including performance work (code‑splitting, memoisation, SSR/SSG) where evidenced.
- [ ] Design‑to‑code builds link the Figma design where possible.
- [ ] Portfolio link prominent and working, with a live demo for each project; no pixel‑perfect clones without interactivity.
- [ ] Experience highlights UI work: component libraries, design handoff, cross‑browser fixes, performance tuning.
- [ ] Lighthouse, bundle size or conversion figures only if logged in `master/metrics-log.csv`.
